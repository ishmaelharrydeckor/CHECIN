## Goal
Add a **Shifts** page where an organization admin (and a manager the admin has allowed) can **create, edit and archive shifts**, and where the admin can **switch shifts on or off, set the scan window, and decide which managers may manage shifts**. The server routes already exist (phase 2); this phase is the screens and the menu entry only. **Assigning people to shifts (the rota), "My shifts" and the refused-scans list are phase 5b: do not build them.**

## The page (`/shifts`)
Use the standard page header (title **"Shifts"**, short subtitle "Plan who works when. Shifts only apply once an administrator switches them on."), then `Tabs` from `src/components/ui/tabs.tsx`:
- **"Shifts"** tab: everyone who can reach the page.
- **"Settings"** and **"Managers"** tabs: **organization admins only** (`isOrgAdmin`). A manager with the switch sees only the "Shifts" tab.

Get the signed-in person's token the way the other pages do (`firebaseAuth.currentUser?.getIdToken()` and an `Authorization: Bearer` header). No other library for data. Write a small `authedFetch` inside the page file (see `departments.tsx`). **Every message shown to the person must be plain language.**

### Tab "Shifts" (`ShiftsList.tsx`, `ShiftFormDialog.tsx`)
- `GET /api/shifts` returns `{ ok, shifts: [{ id, name, type, start, end, graceMinutes, expectedMinutes, createdBy, archived }] }`. Show them in a card list: **name**, a **type pill** (use the status-pill pattern in the style guide; one neutral style for all types is fine), a line of **times** such as `22:00 to 06:00 (overnight)`, `09:00 to 17:00`, or `Flexible, 8 hours`, and `10 minutes grace` when grace is more than 0. Use `src/lib/shift-ui.ts` for all of this text.
- A **"New shift"** button (primary button pattern, one per screen area) opens the form dialog.
- Each row has **Edit** and **Archive** actions (`variant="ghost" size="icon"` with an `aria-label`, destructive style for archive, as in the style guide), shown **only when allowed**: use `canEditShift` from `src/lib/shift-requests.ts` with the caller's `{ uid, role, shiftAdmin }` and the row's `createdBy`. (A manager sees all shifts but can edit only the ones they created.) Archive asks for confirmation with `AlertDialog` ("Archive 'Night'? People already assigned keep it, but it can't be assigned again.") and calls `DELETE /api/shifts?id=...`.
- **Admins only:** a "Show archived" switch that adds `?archived=1`; archived shifts are shown greyed with an "Archived" pill and **no actions** (there is no restore).
- **Form dialog** (create and edit): fields **Name**, **Type** (select: Day, Early, Late, Night, Flexible), **Starts** and **Ends** (`<input type="time">`; hidden for Flexible), **Grace minutes** (number, default 0, helper "How many minutes after the start someone can arrive before they are marked late."), and for Flexible **Expected hours** (a number of hours from 1 to 24, converted to minutes when sent: the API wants `expectedMinutes` from 60 to 1440). Helper under the times: "If the end is earlier than the start, the shift runs past midnight." **Validate before sending** by calling `parseShiftInput` from `src/lib/shift-engine.ts` on exactly the object you will send and showing its error text under the form (`<p role="alert" className="text-xs text-destructive">`). Create sends `POST /api/shifts`; edit sends `PUT /api/shifts` with `{ id, ...fields }`. While saving: disable the buttons and show the spinner pattern. On success close the dialog, refresh the list and `toast.success(...)`. Show the server's error message if it refuses.
- States: **loading** skeletons, **error** with a "Try again" button, **empty** ("No shifts yet. Create your first one, for example 'Day 09:00 to 17:00'."), and the data state. A phone-width layout: rows stack, buttons are at least 40 px tall, nothing scrolls sideways.

### Tab "Settings" (`ShiftSettingsCard.tsx`, admin only)
- `GET /api/shifts/settings` returns `{ ok, shiftsEnabled, shiftScanMode, shiftWindowMinutes, settings }`; `PUT` takes any of those three fields.
- A card titled **"Use shifts"**: a `Switch` with the explanation "When shifts are on, people who have a shift can only check in during their allowed time (from before the shift starts until after it ends). People who have no shift are not affected." Turning it **on** asks for confirmation (`AlertDialog`): "Turn on shifts? From now on, a check-in outside someone's allowed time will be refused. People with no shift assigned are not affected. You can turn this off at any time." Turning it off needs no confirmation. Saving is immediate on confirm, with a spinner and a toast.
- **Allowed time** (the scan window): a number input, in minutes, **30 to 240**, default 120, with the helper "How long before a shift starts, and after it ends, people can still check in." A "Save" button, enabled only when changed. Validate with the same limits as the server (`MIN_WINDOW_MINUTES`, `MAX_WINDOW_MINUTES` from `shift-requests.ts`).
- **Scan mode:** two radio options. **"Strict"** (selected, the default): "A check-in outside the allowed time is refused." **"Lenient"**: shown **disabled**, with the note "Coming soon. For now, a check-in outside the allowed time is always refused." Do not send `shiftScanMode` at all unless it is `"strict"` already.
- A note: "Changes can take up to a minute to reach the check-in screens."

### Tab "Managers" (`ManagerShiftAccessCard.tsx`, admin only)
Copy the pattern of the tablet-access card in `settings.tsx` exactly (read it first). `GET /api/shifts/access` returns `{ ok, managers: [{ uid, displayName, email, shiftAdmin }] }`; `POST` takes `{ targetUid, allowed }` for one manager or `{ all: true, allowed }` for everyone. A `Switch` per manager labelled "Can manage shifts", and the two buttons **"Turn on for all managers"** and **"Turn off for all"**. Explain: "A manager with this on can create their own shifts and assign their own team. Changing it signs that manager out once so it takes effect." States: loading, error with Try again, and empty ("You have no managers yet.").

## `src/lib/shift-ui.ts` (pure; relative imports ending in `.ts`; no React, no Firebase)
Export, with tests:
- `SHIFT_TYPE_LABELS: Record<ShiftType, string>` (Day, Early, Late, Night, Flexible).
- `describeShiftTimes(shift: { type; start; end; expectedMinutes; graceMinutes }): string`, giving for example `22:00 to 06:00 (overnight)`, `09:00 to 17:00`, `Flexible, 8 hours`, `Flexible, 7.5 hours`, with `, 10 minutes grace` appended when grace > 0 (`1 minute grace` singular).
- `hoursToExpectedMinutes(hours: number): number | null` (whole minutes; null if not a number from 1 to 24) and `expectedMinutesToHours(minutes: number | null): string` (`"8"`, `"7.5"`).
- `windowFromInput(raw: string): { ok: true; value: number } | { ok: false; error: string }` using the 30 to 240 rule with a plain sentence for each failure.
Tests (`scripts/tests/shift-ui.test.mjs`): each function, including the singular/plural minute, overnight and flexible cases, 0 grace, `NaN`, blank, decimals, 0 and 25 hours, and the window limits (29, 30, 240, 241, `"abc"`, `"90.5"`).
