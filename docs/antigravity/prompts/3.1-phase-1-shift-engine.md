# Antigravity task: 3.1 Shifts, Phase 1 of 8: the shift engine

**Before you start:** read `docs/antigravity/BRIEF.md` (standing rules), `AGENTS.md`, `docs/REVIEW-CHECKLIST.md`, and **all of `docs/SHIFTS-DESIGN.md`** (this task implements its section 3 and 3b exactly; if the two disagree, the design note wins, and you should say so in the PR).

## Goal
Build the **pure rules engine for shifts**: shift definitions and validation, working out the real start and end of a shift in the organization's timezone (including shifts that cross midnight and daylight-saving days), deciding which shift a scan belongs to, whether it is an in or an out, whether it is late or an early departure, whether a scan must be refused as outside the allowed time, and whether a person is expected or absent on a shift day.

This phase is **logic and tests only**. It must not touch the database, the scan route, any screen, any rule, or any existing file.

- **Pure.** No Firebase, no `fetch`, no `Date.now()`, no `new Date()` with no argument, no randomness, no `console`. Every function takes the current time as a parameter (`nowMs`).

- All times are **local wall-clock times in the organization's timezone** (an IANA name such as `"Africa/Accra"` or `"Europe/London"`), converted to real instants (milliseconds since 1970). Compare **instants**, never minutes-since-midnight (that is what breaks night shifts).
- No `any`. Strict TypeScript must pass.
- Comments say **why**, in plain language, and are as sparse as the surrounding code.

## Constants (export them)
```ts
export type ShiftType = "day" | "early" | "late" | "night" | "flex";
export const SHIFT_TYPES: readonly ShiftType[] = ["day", "early", "late", "night", "flex"];
export const DEFAULT_WINDOW_MINUTES = 120;     // scanning opens this long before a shift starts and closes this long after it ends
export const MIN_WINDOW_MINUTES = 30;
export const MAX_WINDOW_MINUTES = 240;
export const DEFAULT_ABSENT_AFTER_MINUTES = 60; // rostered, no scan, this long after the shift started
export const MAX_ASSIGNMENT_RANGE_DAYS = 62;
export const MAX_SHIFT_MINUTES = 16 * 60;       // longest supported shift
```
A `windowMinutes` argument outside `MIN..MAX` (or not a finite number) is treated as `DEFAULT_WINDOW_MINUTES`.

## Types (export them exactly)
```ts
/** A shift's details as copied onto an assignment, so editing a shift later never rewrites history. */
export interface ShiftSnapshot {
  shiftId: string;
  name: string;
  type: ShiftType;
  start: string | null;          // "HH:MM" 24-hour; null for flex
  end: string | null;            // "HH:MM"; null for flex
  graceMinutes: number;          // whole minutes, 0 or more
  expectedMinutes: number | null;// flex only
}
export interface ShiftAssignment { dayKey: string; shift: ShiftSnapshot } // dayKey is the day the shift STARTS

export interface ShiftWindow {
  startMs: number | null;        // null for flex
  endMs: number | null;          // null for flex
  opensMs: number;               // first instant a scan is allowed (inclusive)
  closesMs: number;              // last instant a scan is allowed (inclusive)
}
export interface ShiftState { lastType: "in" | "out" | null } // the person's last scan on that shift day
export type ScanDirection = "in" | "out";
```

## Functions to build (export each; exact names and behaviour)

### 1. `parseShiftInput(raw: unknown)`
Returns `{ ok: true; value: { name; type; start; end; graceMinutes; expectedMinutes } } | { ok: false; error: string }`. It validates what an admin typed. Rules:
- `name`: a string; trimmed, repeated spaces collapsed to one, control characters removed; 1 to 40 characters after cleaning.
- `type`: one of `SHIFT_TYPES`.
- **Non-flex:** `start` and `end` are required and must be `"HH:MM"` 24-hour (`00:00` to `23:59`, two digits each). `start` and `end` must **not be equal**. The shift length (see `shiftMinutes`) must be **at most `MAX_SHIFT_MINUTES`**. `expectedMinutes` is ignored and returned as `null`.
- **Flex:** `start` and `end` are ignored and returned as `null`. `expectedMinutes` is required: a whole number from 60 to 1440 (24 hours).
- `graceMinutes`: optional, default 0; a whole number from 0 to 120. Anything else is an error (never silently corrected).
- Errors are short plain sentences a non-technical admin can read, for example `"Choose a name of 1 to 40 characters."`, `"A shift cannot start and end at the same time."`, `"Shifts can be at most 16 hours long."`. One error is returned at a time (the first problem found).

### 2. `crossesMidnight(start: string, end: string): boolean`
True when `end` is earlier than `start` (for example 22:00 to 06:00). Both are valid `HH:MM` strings.

### 3. `shiftMinutes(start: string, end: string): number`
The **wall-clock** length in minutes, counting across midnight (22:00 to 06:00 is 480). Ignores daylight saving on purpose; real elapsed time comes from `shiftWindow`.

### 4. `zonedTimeToMs(day: string, hhmm: string, timezone: string): number`
The real instant (milliseconds) at which the clock in `timezone` first reads `hhmm` on calendar day `day` (`"YYYY-MM-DD"`). Rules for the two awkward cases:
- **A time that does not exist** (clocks jump forward): use the instant **after the gap by the same amount**, i.e. treat `02:30` on a spring-forward day as `03:30`.
- **A time that happens twice** (clocks go back): use the **first** occurrence.
Implement it without a date library (use `Intl.DateTimeFormat` with the timezone, and verify your result by formatting it back). An invalid timezone behaves as `"UTC"`.

### 5. `shiftWindow(assignment: ShiftAssignment, timezone: string, windowMinutes?: number): ShiftWindow`
- Non-flex: `startMs = zonedTimeToMs(assignment.dayKey, start)`. `endMs = zonedTimeToMs(day, end)` where `day` is `assignment.dayKey` if the shift does not cross midnight and `addDays(assignment.dayKey, 1)` if it does. `opensMs = startMs - windowMinutes*60000`; `closesMs = endMs + windowMinutes*60000`.
- **Flex:** `startMs = endMs = null`; `opensMs = startOfDayMs(dayKey, timezone)`; `closesMs = startOfDayMs(addDays(dayKey, 1), timezone) + windowMinutes*60000`.
- Because the window is built from real instants, a night shift on a daylight-saving changeover night is correctly one hour longer or shorter in real time.

### 6. `classifyScan(input)`
```ts
input: {
  nowMs: number;
  timezone: string;
  assignments: readonly ShiftAssignment[];             // the person's assignments for yesterday, today and tomorrow (any order; malformed ones ignored)
  states: Readonly<Record<string, ShiftState>>;        // keyed by shift day; a missing key means lastType null
  windowMinutes?: number;
}
returns
  | { kind: "matched"; shiftDay: string; shift: ShiftSnapshot; direction: ScanDirection; late: boolean; earlyDeparture: boolean; window: ShiftWindow }
  | { kind: "outside"; reason: "too_early" | "too_late"; shiftDay: string; shift: ShiftSnapshot; window: ShiftWindow }
  | { kind: "unassigned" }
```
**Which shift a scan belongs to.** Compute each assignment's window. The candidates are the assignments whose window contains `nowMs` (**both ends inclusive**).
- Exactly one candidate: that one.
- Several (windows can overlap, for example a night shift whose window ends after the next day shift's window opens). Decide in this order:
  1. If any candidate has `states[shiftDay].lastType === "in"` (the person is still on that shift, so this scan is their check-out), keep only those.
  2. Otherwise drop every candidate whose shift has **already ended** (non-flex and `endMs <= nowMs`) **and** whose `lastType` is `"out"` (it is finished and closed), **unless that would drop all of them**, in which case keep them all (a re-scan after check-out is a re-entry).
  3. Among what remains, prefer the candidate with the **latest `startMs` that is `<= nowMs`** (flex counts as started); if none has started, the one with the **earliest `opensMs`**. Break any remaining tie by the earlier `dayKey`, then by `shiftId`.
- None: apply the **outside** rule below.

**Direction.** `lastType` null → `"in"`; `"in"` → `"out"`; `"out"` → `"in"`.

**Late.** True only when `direction` is `"in"`, `lastType` is `null` (the first check-in of that shift day), the shift is not flex, and the scan's **minute** is after `start + graceMinutes`. Compare whole minutes: `Math.floor(nowMs/60000) > Math.floor(startMs/60000) + graceMinutes`. So with grace 0, a scan at 09:00:59 is **not** late and 09:01:00 **is**.

**Early departure.** True only when `direction` is `"out"`, the shift is not flex, and `Math.floor(nowMs/60000) < Math.floor(endMs/60000)`.

**The outside rule** (nothing matched). Let `today` = `dayKey(nowMs, timezone)` and `yesterday` = `addDays(today, -1)`. The **relevant** assignments are those whose `dayKey` is `today` or `yesterday`.
- No relevant assignment → `{ kind: "unassigned" }` (the caller then behaves exactly as it does today).
- Otherwise, if any relevant window has `opensMs > nowMs`, return `too_early` for the one with the **smallest `opensMs`**.
- Otherwise return `too_late` for the relevant one with the **largest `closesMs`**.
(Assignments for tomorrow never cause a refusal on their own.)

### 7. `describeOutside(c, timezone: string): string`
`c` is the `"outside"` result. Returns the plain sentence shown on the phone (the phone screen adds "Your check-in was not recorded." in front, so **do not** include it). Times are `"HH:MM"` in `timezone`:
- `too_early`, non-flex: `Your shift starts at 22:00. Scanning opens at 20:00.` (the shift's own `start`, then the window's `opensMs`).
- `too_late`, non-flex: `Your shift ended at 06:00 and scanning closed at 08:00. Please speak to your manager.`
- Flex (either reason): `Your flexible shift for 2026-10-12 has closed. Please speak to your manager.` (use the shift day).

### 8. `shiftDayStatus(input)`
```ts
input: { assignment: ShiftAssignment | null; hasScan: boolean; onLeave: boolean; isHoliday: boolean;
         nowMs: number; timezone: string; absentAfterMinutes?: number }
returns "present" | "on_leave" | "holiday" | "not_rostered" | "expected" | "absent"
```
In this order: a scan → `"present"`; approved leave → `"on_leave"`; a holiday → `"holiday"`; no assignment → `"not_rostered"`. With an assignment and no scan: before `startMs + absentAfterMinutes` → `"expected"`, at or after → `"absent"`. For **flex**, the person is `"expected"` until the shift day has ended (the instant `startOfDayMs(addDays(dayKey,1), timezone)`), then `"absent"`. `absentAfterMinutes` outside 0..720 or not finite → `DEFAULT_ABSENT_AFTER_MINUTES`.

### 9. `expandAssignmentRange(input)`
```ts
input: { fromDay: string; toDay: string; weekdays: readonly number[] }   // weekdays: 0 = Monday ... 6 = Sunday
returns { ok: true; days: string[] } | { ok: false; error: string }
```
Returns every `YYYY-MM-DD` from `fromDay` to `toDay` **inclusive** whose weekday is in `weekdays`, oldest first, without duplicates. Errors (plain sentences): invalid dates; `fromDay` after `toDay`; a span longer than `MAX_ASSIGNMENT_RANGE_DAYS` days **counting both ends**; no weekday chosen or a weekday outside 0..6; or no matching day in the range.

### 10. `assignmentId(employeeId: string, day: string): string`
Returns `` `${employeeId}_${day}` `` (the deterministic id that makes a retried request harmless). Throw an `Error` if either part is empty or contains `/`.

## Tests (`scripts/tests/shift-engine.test.mjs`, Node test runner)
Follow the style of `scripts/tests/manager-history.test.mjs` (`import test from "node:test"; import assert from "node:assert/strict";`, import from `../../src/lib/shift-engine.ts`). **Every rule above gets at least one test, and these exact cases must be included** (all times local to the stated timezone; `2026-10-12` is a Monday):

**zonedTimeToMs**
- `("2026-10-12","22:00","Africa/Accra")` equals `Date.UTC(2026,9,12,22,0)` (Accra is UTC+0, no daylight saving).
- Gap: `("2026-03-29","01:30","Europe/London")` equals `Date.UTC(2026,2,29,1,30)` (that is 02:30 BST).
- Repeat: `("2026-10-25","01:30","Europe/London")` equals `Date.UTC(2026,9,25,0,30)` (the first, BST, occurrence).
- Gap: `("2026-03-08","02:30","America/New_York")` equals `Date.UTC(2026,2,8,7,30)` (03:30 EDT).
- Repeat: `("2026-11-01","01:30","America/New_York")` equals `Date.UTC(2026,10,1,5,30)` (EDT).
- An invalid timezone name behaves as UTC.

**shiftWindow**
- Day shift 09:00 to 17:00 in Africa/Accra on 2026-10-12: start/end/opens/closes are 09:00, 17:00, 07:00, 19:00 UTC, with default window.
- Night shift 22:00 to 06:00: `endMs` is on 2026-10-13; `endMs - startMs` is exactly 8 hours.
- Night shift Saturday 2026-10-24 22:00 to 06:00 in Europe/London (the clocks go back during it): `endMs - startMs` is **9 hours** of real time.
- Night shift Saturday 2026-03-28 22:00 to 06:00 in Europe/London (clocks go forward): **7 hours**.
- Flex: `startMs`/`endMs` null, opens at the start of the shift day, closes at the start of the next day plus the window.
- A window length of 20, 500 or `NaN` becomes 120.

**classifyScan** (use Africa/Accra, Day 09:00 to 17:00 grace 0 and Night 22:00 to 06:00 grace 10 as the two shifts)
- Boundaries: a scan exactly at `opensMs` is matched; one millisecond earlier is outside/too_early; exactly at `closesMs` is matched; one millisecond later is outside/too_late.
- Late: 09:00:59 not late; 09:01:00 late. With grace 10: 22:10:59 not late, 22:11:00 late.
- Late only on the first check-in: the same shift day with `lastType: "out"` and a scan at 09:30 is `direction: "in"` and `late: false`.
- Early departure: an out scan at 16:59 is early; at 17:00 is not.
- Night shift across midnight: Monday 21:55 is `in` for shift day Monday; Tuesday 06:05 is `out` for shift day **Monday** (state `lastType: "in"` under Monday), not late, not early; the shift day is Monday and not Tuesday.
- Overlap: a Monday night shift (window closes Tuesday 08:00) and a Tuesday day shift (window opens Tuesday 07:00); a scan at Tuesday 07:30 with `lastType: "in"` on Monday → matched to Monday (check-out); the same scan with Monday `lastType: "out"` (they checked out at 06:00) → matched to Tuesday (check-in). Also: only the Monday night shift is assigned, state `"out"`, scan at Tuesday 07:00 → still matched to Monday, direction `"in"` (a re-entry).
- Flex is never late, even at 23:59 (and its early-departure flag is always false).
- Outside, too early: Monday 15:00 with a Monday night shift only → `too_early`, `describeOutside` says exactly `Your shift starts at 22:00. Scanning opens at 20:00.`
- Outside, too late: Tuesday 10:00 with only the Monday night shift → `too_late`, text `Your shift ended at 06:00 and scanning closed at 08:00. Please speak to your manager.`
- Both a closed yesterday shift and an upcoming today shift → `too_early` about today's.
- Unassigned: no assignments, or only an assignment for **tomorrow** whose window is not yet open, or assignments for days other than today/yesterday whose windows do not contain the scan → `unassigned`.
- Malformed assignments (bad `dayKey`, missing shift) are ignored and never throw.
- A different timezone gives different instants for the same assignment (same wall time).
- The input arrays are not modified.

**shiftDayStatus** — a table covering every branch: scan beats leave beats holiday beats rostered; not rostered; expected one minute before `start + 60`; absent at exactly `start + 60`; a custom `absentAfterMinutes`; flex expected until the end of the day then absent; a night shift that started yesterday at 22:00: at 01:00 today it is `present` with a scan and `absent` without one (it started three hours earlier).

**parseShiftInput** — valid day, valid night, valid flex; each error case (empty name, 41-character name, unknown type, bad time formats `"9:00"`, `"24:00"`, `"09:60"`, equal start and end, over 16 hours, grace 121, grace `1.5`, grace `"5"`, flex without or with out-of-range `expectedMinutes`); name cleaning.

**expandAssignmentRange**
- Monday to Friday over `2026-10-12`..`2026-10-18` gives exactly the five weekdays.
- A span of exactly 62 days (`2026-10-12`..`2026-12-12`) is allowed; `2026-10-12`..`2026-12-13` (63 days) is refused.
- `fromDay` after `toDay`, no weekday, weekday `7`, a range with no matching day, and an invalid date are each refused with a sentence; duplicate weekdays do not duplicate days.

**assignmentId** — the normal case; empty parts and a slash throw.
