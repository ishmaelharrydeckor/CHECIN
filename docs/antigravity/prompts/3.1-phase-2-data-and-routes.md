## The pure part: `src/lib/shift-requests.ts`
Relative imports ending in `.ts`; no Firebase; no `Date.now()` (take `today` as a parameter). Import from `./shift-engine.ts`: `parseShiftInput`, `expandAssignmentRange`, `assignmentId`, `MIN_WINDOW_MINUTES`, `MAX_WINDOW_MINUTES`, `DEFAULT_WINDOW_MINUTES`, `MAX_ASSIGNMENT_RANGE_DAYS`, and the types. Export:

```ts
export const MAX_PEOPLE_PER_REQUEST = 50;
export const MAX_WRITES_PER_REQUEST = 500;     // people x days
export const MAX_ACTIVE_SHIFTS = 100;
export const ASSIGNMENT_READ_CAP = 4000;

export type ScanMode = "strict" | "lenient";
export interface ShiftSettings { shiftsEnabled: boolean; shiftScanMode: ScanMode; shiftWindowMinutes: number }
export const DEFAULT_SHIFT_SETTINGS: ShiftSettings = { shiftsEnabled: false, shiftScanMode: "strict", shiftWindowMinutes: DEFAULT_WINDOW_MINUTES };

/** Reads what is saved on the organization; anything missing or wrong falls back to the default for that field. */
export function readShiftSettings(orgData: unknown): ShiftSettings

/** What an admin sends to change settings: any of the three fields; others untouched. */
export function parseSettingsInput(raw: unknown): { ok: true; value: Partial<ShiftSettings> } | { ok: false; error: string }
// shiftsEnabled must be a boolean; shiftScanMode "strict" | "lenient"; shiftWindowMinutes a whole number MIN..MAX. Nothing valid sent is an error. Unknown fields are ignored.

export interface CallerLike { uid: string; role: string | null; shiftAdmin: boolean }
/** Org admin always; a manager only when their shiftAdmin switch is on; nobody else. */
export function canManageShifts(caller: CallerLike): boolean
/** Admin: any shift. Manager with the switch: only a shift they created (createdBy equals their uid). */
export function canEditShift(caller: CallerLike, shiftCreatedBy: string | null): boolean
/** Admin: anyone in the organization with role employee or manager. Manager with the switch: only people whose managerId is their own uid (that includes themself). Never an org_admin target. */
export function canAssignTo(caller: CallerLike, target: { role: string | null; managerId: string | null; uid: string }): boolean

export interface AssignRequest { shiftId: string; employeeIds: string[]; days: string[] }
export function parseAssignRequest(raw: unknown, today: string): { ok: true; value: AssignRequest } | { ok: false; error: string }
// { shiftId: string, employeeIds: string[], fromDay, toDay, weekdays: number[] }
//  - shiftId non-empty string; employeeIds 1..MAX_PEOPLE_PER_REQUEST distinct non-empty strings (duplicates removed, not an error)
//  - days come from expandAssignmentRange (reuse its errors)
//  - EVERY day must be >= today ("Shifts can only be assigned from today onwards.")
//  - employeeIds.length * days.length <= MAX_WRITES_PER_REQUEST, else a plain sentence saying to choose fewer people or a shorter range

export interface ClearRequest { employeeIds: string[]; days: string[] }
export function parseClearRequest(raw: unknown, today: string): { ok: true; value: ClearRequest } | { ok: false; error: string }
// { employeeIds, fromDay, toDay } (all 7 weekdays are cleared); same limits and the same "today onwards" rule

/** Turns a stored shift document into the snapshot copied onto assignments. Returns null if the document is damaged. */
export function snapshotFromShiftDoc(id: string, doc: unknown): ShiftSnapshot | null
```
Errors are short plain sentences. Never silently correct input.

## The routes
All routes: identity, role, `orgId` and `managerId` come **only** from `verifyCallerToken(request.headers.get("authorization"), { checkRevoked: true })` (use `checkRevoked` on every write). **Never read `orgId`, `role`, `managerId` or `uid` of the caller from the body, query or URL.** Every document you write gets `orgId` from the token. Every read starts with `orgId`, has a `.limit(...)`, and needs no index you have not added. Writes call `checkRateLimit` (Firestore-backed; 60 per hour per caller, key prefix `shifts_`) and write one `logEvent(...)` line with `action`, `outcome`, `correlationId`, `orgId`, `uid` and small non-secret `fields`. Plain-language error messages for a non-technical admin. `canManageShifts` needs the caller's `shiftAdmin` claim from the token (`caller.shiftAdmin === true`).

### `/api/shifts` (shifts)
- **GET**: any signed-in member of an organization (admin, manager, employee). Returns the organization's shifts, `limit(200)`, not archived (`?archived=1` includes archived ones, **admin only**). Fields per shift: `id, name, type, start, end, graceMinutes, expectedMinutes, createdBy, archived`.
- **POST**: `canManageShifts`. Body validated by `parseShiftInput`. Refuse when the organization already has `MAX_ACTIVE_SHIFTS` non-archived shifts. Creates `shifts/{autoId}` with `orgId` (token), the validated fields, `createdBy` (token uid), `createdAt`, `updatedAt` (ISO), `archived: false`.
- **PUT**: body `{ id, ...shift fields }`. Load the shift; a shift of another organization looks exactly like a missing one (**404**, the same message). `canEditShift`. Re-validate with `parseShiftInput`. Update the fields and `updatedAt`. **Editing a shift never touches existing assignments** (they keep their copied snapshot).
- **DELETE** `?id=`: same checks; sets `archived: true` (a shift is never removed, so history stays readable). Archiving twice is fine.

### `/api/shifts/assignments`
- **GET** `?from=YYYY-MM-DD&to=YYYY-MM-DD` (and optional `employeeId`): the range must be valid and at most `MAX_ASSIGNMENT_RANGE_DAYS` days (use `expandAssignmentRange` with all seven weekdays to validate). Scope from the token only: **org admin** the whole organization; **manager** only `managerId == caller.uid`; **employee** only `employeeId == caller.uid` (an `employeeId` filter can narrow but never widen what a role may see). `limit(ASSIGNMENT_READ_CAP)`; return `truncated: true` if the cap is hit. Each row: `id, employeeId, employeeName, managerId, dayKey, shift` (the snapshot).
- **POST**: `canManageShifts`. `parseAssignRequest` with `today` = `dayKey(Date.now(), organization timezone)` (read the organization document once). Then:
  1. Load the shift; same organization and not archived, else 404/400 with a plain message. Build its snapshot with `snapshotFromShiftDoc`.
  2. Resolve every person from **Firebase Auth claims** in batches of at most 100 with `getAuthAdmin().getUsers(...)` (never trust the `users` document for role or manager). A person who is not in the caller's organization is reported as not found (same wording for "unknown" and "other organization"). Apply `canAssignTo`; a person the caller may not assign is refused with a plain sentence naming nobody from another organization.
  3. Read display names with one `firestoreAdmin.getAll(...)` over the people's `users` documents (at most 50).
  4. For **today only**, a person who already has a daily summary for today (`daily_summaries/{summaryDocId(employeeId, today)}`, read with one `getAll`) is **skipped** for today: their day is not changed because hours are already recorded. Other days are written.
  5. Write with `firestoreAdmin.batch()` (at most 500 sets), document id `assignmentId(employeeId, dayKey)` so a retry or a re-assign **replaces** instead of duplicating. Document fields: `orgId` (token), `managerId` (the person's current manager from their claims), `employeeId`, `employeeName`, `dayKey`, `shiftId`, `shift` (the snapshot), `assignedBy` (token uid), `assignedAt` (ISO).
  6. Respond `{ ok: true, written: number, skipped: { employeeId, dayKey, reason }[] }`.
- **DELETE**: `canManageShifts`. Body `{ employeeIds, fromDay, toDay }` through `parseClearRequest`. Same person checks as POST. Deletes the assignment documents (by deterministic id) for days from today onwards, skipping today for anyone who already has a summary. Respond `{ ok: true, removed: number, skipped: [...] }`.

### `/api/shifts/settings`
- **GET**: any signed-in member. Returns `readShiftSettings(organization document)`.
- **PUT**: **org admin only**. `parseSettingsInput`; merge the given fields into the organization document (`shiftsEnabled`, `shiftScanMode`, `shiftWindowMinutes`, and `updatedAt`) with `set(..., { merge: true })`. Respond with the saved settings. Do **not** touch any other organization field.

### `/api/shifts/access`
Copy `kiosk-access.ts` in structure and behaviour (org admin only, `checkRevoked`, list managers from Firebase Auth in batches of 100, single target or `{ all: true, allowed }`, same 404 for unknown / other organization / not a manager, `revokeUserSessions` after a change so it applies at once, `logEvent`). The claim is **`shiftAdmin`** and the helper that writes it lives in `src/lib/shift-access.server.ts` as `setShiftAdminClaim(uid, allowed)` (merge one key into existing claims, as described above), together with `canManageShifts`-style helpers you need. The list returns `{ uid, displayName, email, shiftAdmin }` per manager.

## `firestore.rules` (add exactly these two blocks, just above the "Default Deny" catch-all)
```
    // ---- Shifts (templates) and shift assignments ----
    // Written by the server only (docs/SHIFTS-DESIGN.md). Everyone in the organization can read the
    // shift templates; an assignment is readable by the person, their manager and org admins.
    match /shifts/{shiftId} {
      allow read: if inOrg(resource.data);
      allow create, update, delete: if false;
    }
    match /shift_assignments/{assignmentId} {
      allow read: if inOrg(resource.data) && (
        isOrgAdmin() ||
        (isManager() && resource.data.managerId == request.auth.uid) ||
        resource.data.employeeId == request.auth.uid
      );
      allow create, update, delete: if false;
    }
```
No other rule may change. Mark these two blocks clearly in the PR so the integrator can review and deploy them.
